## 3. Capabilities genuinely missing vs the frozen contract

- Generic staged lifecycle types (plan → prepared → activated → exit → cleanup-verify):
  zero matches repo-wide; current model is one-shot `CapabilitySet` → `Sandbox::apply_*`.
- Pre-exec hold + opaque single-use release capability (activation gate): no discrete
  "prepared, not released" state exists; apply and exec are one synchronous flow.
- Typed exit facts: waitpid results collapse to `i32` (128+signal); `_exit(126/127)`
  sentinels collide with customer exit codes; no ActivationOccurred / SupervisorFailure /
  SandboxApplicationFailure distinction; no positive "customer code started" observation.
- Typed cleanup verification (ConfirmedAbsent/StillPresent/Indeterminate/Unsupported):
  only bool liveness; SIGKILL path never re-checks; cgroup teardown result swallowed.
  (Addressed in the fork by F6; the upstream gap statement stands for 149579a7.)
- Machine-readable support report: `SupportInfo{is_supported: bool, …, details: String}`;
  macOS hardcodes true; `DetectedAbi` granularity internal-only.
- Generic event sink: audit log is a concrete file writer with a closed enum; no subscriber
  API; no per-event fidelity (direct vs reconstructed) flag.
- Library-level session/PTY/attach/wait/stop/recover APIs: all CLI-crate-private; no `wait`
  operation exists even in the CLI.
- Mode-aware fs capability vocabulary: `AccessMode` is Read/Write/ReadWrite only; no
  append/create/truncate/remove/rename/metadata/exec toggles; atomic-write is a CLI regex
  hack (macOS); exec unconditionally allowed on macOS profiles.
- Deterministic concurrency harness: no loom/miri/fuzz anywhere; no race tests for
  stop/attach/activate/wait.
- Session schema versioning: `SessionRecord` has no version field. (Addressed in the fork by F7
  for the library store; the upstream gap statement stands for 149579a7 and for the CLI's own
  registry, which is unchanged.)
- Linux: SignalMode::Isolated silently degrades without V6 scoping (debug! only) —
  candidate fail-closed fix.

| F9 | Detached supervisor via self-re-exec entry hook + control protocol v1 (ADR-0002; contract §11). **The mechanism:** a library cannot re-exec "the nono binary" (it has none) and cannot fork a *long-running* supervisor out of a threaded caller (allocator locks after `fork`; the macOS ObjC runtime aborts). So the supervisor is **this binary re-executed**, opting in through one line of embedder cooperation — `nono::lifecycle::supervisor_entry()` as the first statement of `main`. It is a no-op without a private environment marker (`NONO_LIFECYCLE_SUPERVISOR`, **protocol not configuration**, removed from the environment before any other work so it can never be inherited by a customer child); with it, it never returns. **Two forks, both ADR-0001 syscall-only-to-exec:** the launcher forks an intermediate that forks the supervisor-to-be and exits (so the supervisor is reparented to init and a long-lived launcher never collects a zombie it cannot be expected to reap); the supervisor-to-be `setsid`s, points 0/1/2 at `/dev/null`, forks the **customer child** through the unchanged `child_main`, writes a bootstrap blob, clears close-on-exec on its five survivors, sweeps every other descriptor, and `execve`s. `execve` replaces an image and not a process, so the customer child is still the child of the same pid afterwards — which is the entire reason a detached run's exit facts are observable. **Nothing about the plan crosses the exec**: the exec image, argv, environment and platform policy are built and used on the launcher's side, so a `CapabilitySet` is never serialized and re-trusted. **Secrets:** the gate's release/abort pair travels on a private bootstrap pipe (the customer child already holds it) and is zeroized after parse; the **activation token is drawn in the supervisor, after the exec**, and handed back on the readiness handshake — so it never exists in the customer child's address space at all, which is strictly stronger than the attached path. **No bind race:** the launcher binds and listens on `<store>/<session>.sock` (unlink-guarded, 0600 inside the 0700 store, `sockaddr_un` length refused not truncated) *before* the fork and passes the **listening descriptor** through the exec, so readiness implies a socket that has been listening since before the supervisor existed. Readiness is a byte-tagged handshake carrying the supervisor's own `ProcessIdentity` and the token, `poll`-bounded, and a binary whose `main` lacks the hook fails closed at the deadline with `PrepareError::SupervisorUnresponsive`, **which names the function**. **Supervisor loop:** single-threaded `poll` over {listening socket, held child's status descriptor, `SIGCHLD` self-pipe (errno-preserving handler), connected client}, one client at a time (a second is told `ControlRefusal::Busy` and closed, never queued), `waitpid(WNOHANG)` through a new `ActivatedSandbox::try_wait`, every transition and the `SandboxExit` persisted, serving continues after a client detaches, and the process exits on `CleanupVerified` or after `IDLE_AFTER_TERMINAL_GRACE` (300 s, documented) with a terminal state and nobody connected. **Protocol v1** (`lifecycle/protocol.rs`): u32-LE length-prefixed frames, `MAX_CONTROL_FRAME_BYTES` = 64 KiB checked **from the prefix before a byte of body is read or allocated**; hello first in both directions carrying {version, session, generation}, each checked on both sides; ops `Activate{token}` / `Wait{deadline_millis}` / `Stop` / `Status` / `VerifyCleanup` / `Goodbye`; replies carry the module's **existing typed results** (`ActivationError`, `StopError`, `SandboxExit`, `CleanupVerification`, `LifecycleState`) rather than rendered strings — which is why `ActivationError`/`StopError` gained serde derives; peer-uid checked at accept by **reusing** `supervisor::socket::peer_credentials` (a foreign uid is closed without a word, since answering would confirm the session exists); the token is compared supervisor-side by the existing gate digest, never persisted, and redacted from `ControlRequest`'s hand-written `Debug`. **Every read and write on both sides is `poll`-deadline-bounded**, closing ADR-0001's unbounded-read residual for this path. **Client:** `DetachedSession::{activate, wait, stop, status, verify_cleanup, detach}` — dropping it closes a socket and the run carries on, which is the opposite of every other handle in the module. **Record schema v2** (`docs/lifecycle/session-record-v2.md`): adds `supervisor: Option<ProcessIdentity>`, `exit: Option<SandboxExit>` (witnessed exit facts, durable across a caller restart) and `events: Vec<LifecycleEvent>` (bounded ring, `DETACHED_EVENT_RING_CAPACITY` = 32, oldest dropped — honest, because `EventSink` is caller-side and a detached supervisor has no caller to deliver to). **v1 compatibility is explicit, not lenient**: the version probe chooses between two `deny_unknown_fields` shapes, a v1 record is parsed as v1 and upgraded in memory (no supervisor, no exit, empty ring — absence reported, never invented), and an unimplemented version is still `UnsupportedSchemaVersion`. **Recovery:** `reconcile` gains a `SupervisorPresence` input ({`NeverDetached`, `Alive`, `Gone`}, fail-closed via `ProcessIdentity::is_same_process`) and a `RecoveryDecision::Attachable` that outranks every child probe but **not** `AlreadyVerified`; an attachable record is *not* moved to `Failed` (the live supervisor owns it), and a `Gone` supervisor's stale socket is unlinked by the store where its staleness was just established. `SupportReport.detached_supervisor` becomes `Available`/`PlatformApi` with the entry-hook precondition in `why_not_probed`;
